# BranchForge 逐行三方合并内核

纯 Python 库，不做仓库管理、提交存储或人工解决流程。调用方直接提供同一
文件的共同祖先 `base` 与两个分支版本 `ours`、`theirs`（均为字节串）。

## API

```python
from branchforge import diff, merge, Edit, StableBlock, ConflictBlock
```

- `diff(base, target) -> list[Edit]`：把 `base` 变成 `target` 的编辑序列。
  每项 `Edit(start, end, replacement)` 表示把基线行区间 `[start, end)`
  替换为 `replacement` 字节；`start == end` 表示纯插入。删除行数加插入
  行数最小；没有被保留行隔开的连续改动合并为一项。
- `merge(base, ours, theirs) -> list[StableBlock | ConflictBlock]`：按文件
  顺序排列的普通字节块与冲突块。`ConflictBlock` 保留基线行区间
  `(base_start, base_end)` 及该范围对应的 `base`、`ours`、`theirs`
  原文，调用方无需重新计算差异即可展示冲突。

## 行模型

仅以 LF 分行，LF 属于该行；空串是零行，末行可以没有 LF。行相等按完整
字节判断。不做换行归一化、不删空白；输入中的冲突标记文本只视为普通内容。

## diff 决胜规则（确定性）

算法为 Myers O((N+M)·D) 贪心搜索的线性空间（分治中点蛇）变体，额外内存
O(N+M)，不生成与 N·M 同阶的状态。重复行导致多种最短对齐时：

- 前向扫描中，删除与插入候选并列（`V[k-1] + 1 == V[k+1]`）时优先删除；
- 反向扫描中，并列时优先选择上移路径（对应反向的插入）；
- 全过程无随机性，同一输入永远产生同一编辑序列。

## 合并语义

- 两侧非空编辑区间共享基线行时相碰；纯插入仅在位置严格落入另一编辑区间
  内部时相碰；两个纯插入同位置相碰；区间仅首尾相接不相碰。
- 冲突区域是相碰关系传递闭包的最小编辑集合，不扩大、不拆散；只含一侧
  编辑的区域直接采纳。
- 两侧编辑的区域分别重放各侧编辑，结果一致则只保留一次，否则输出冲突块；
  区域内未被编辑覆盖的基线内容保留在对应侧原文中。
- 边界插入不与相邻替换制造冲突，输出时在前一替换之后、后一替换之前。

## 运行测试

```sh
python3 -m pytest tests/ -q
```

覆盖：小输入独立参考判定（DP 最短路 + 重放逐字节校验，含大量重复行）、
编辑串联成区、同位置插入、删除区间两端插入、末行无 LF、冲突标记按普通
内容处理，以及可复现的 100000 行性能/内存测试（实测约 2s、峰值额外内存
约 20 MiB，限制 128 MiB）。
